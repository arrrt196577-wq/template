# 第一期功能规划

- 创建日期：2026-10-19（Asia/Hong_Kong）
- 最近修订：2026-10-21，建立 Go 运行、连接池、显式迁移、HTTP 生命周期与基础验证骨架；登录及其他业务仍未实现。
- 状态：前端、Java 与 Go 均有基础骨架；Go 已完成配置、日志、健康检查、迁移和事务基础验证。下列业务功能尚未实现，共同契约与 M1、第一期验收尚未完成。
- 技术栈：Java 后端采用 Java、Spring Boot、Spring Cloud；Go 后端采用 Go、Gin；共用前端采用 Vue 3、TypeScript、Element Plus。
- 相关文档：[技术栈规划](技术栈规划_2026-10-19.md)、[API 规划](API规划_2026-10-20.md)（接口与鉴权建议，尚待确定）。

## 一、第一期目标

交付 Java 与 Go 两套可独立使用的后端模板，以及一套共用的管理端前端。每套后端均能从空数据库启动、完成登录与授权、支持标准管理页面并追溯关键操作。后续项目可按语言选择后端，基于完整链路复制和扩展自己的业务模块。

第一期优先解决可运行、可复用和权限边界三个问题，控制产品功能与基础设施范围。

## 二、规划前提与边界

- Java、Go 后端遵循同一份接口契约和本规划中的服务端功能要求，分别实现、联调和验收；F05 为共用前端能力，须分别对接两套后端验证。
- 每个派生项目仅选择 Java 或 Go 其中一套后端，并复用前端模板；不设计同一项目内的双后端部署或运行时切换。两种组合在模板各自独立的验收环境中验证，各派生项目独立管理数据库及登录状态。
- 两套后端通过 Authorization: Bearer 传递 Token，暂不采用 Cookie 承载认证凭据；Go 已确定随机不透明 Token + PostgreSQL 会话记录、Argon2id 与 RBAC 中间件。Java Token 类型与组件、前端存储、有效期、刷新、多端登录及并发细则仍待细化，尚无登录实现。
- 按单租户管理后台规划，暂不设计组织、部门及复杂数据范围规则；个人资料和密码仍须严格限制为本人操作。
- 示例数据采用明确的共享访问模型：具备对应权限的账号可访问示例记录；新项目引入私有数据时必须另行定义访问范围。
- 权限采用用户关联角色、角色关联权限的 RBAC 模型；权限标识由代码维护，前端菜单与按钮映射这些标识。
- 第一期开设角色授权页面，菜单结构及权限目录由代码维护，暂不开发动态菜单和权限定义编辑器。
- Spring Cloud 已纳入 Java 后端技术栈，具体组件、服务边界和部署拓扑仍待细化；网关、注册中心及配置中心不默认全部纳入首期交付，Go 后端配套基础设施另行按需评估。
- 主数据库统一选定 PostgreSQL，生产版本基线待定；Java 已接入 MyBatis-Plus + Flyway 依赖与配置，Go 已接入 GORM + goose、slog 与 testing + httptest，固定版本见技术栈规划。两套后端均无业务表、业务迁移 SQL 或持久化业务；Go 已用 PostgreSQL 18.6 验证连接、迁移与事务基础能力。

## 三、第一期必做功能

### F01 工程与接口基线

实现内容：

- 分别建立 Java、Go 后端工程及共用前端工程，各自提供配置示例及开发环境说明，区分开发、测试与生产所需配置。
- 建立数据库迁移和受控的初始管理员创建流程，避免重复初始化和公开固定生产密码。
- 统一接口响应、参数校验、异常处理、分页与排序约定，以及前端请求和错误提示方式。
- 定义两套后端共用的接口路径、方法、认证交互、字段类型、HTTP 状态码、错误语义、时间格式和权限标识，使用同一组契约场景验证；两种语言内部的组件与实现方式分别选型。
- 明确未登录、无权限、参数错误及业务冲突的响应语义；错误响应中不暴露堆栈和敏感配置。
- 提供基本健康检查和应用日志，便于确认启动状态及定位请求失败。

验收：两套后端分别按说明从空数据库启动，重复启动不会重复创建初始化数据；共用前端分别完成真实接口请求，非法参数均能够在服务端被拒绝，相同契约场景的对外行为一致。

### F02 登录、会话与个人中心

实现内容：

- 用户名与密码登录、退出、当前用户信息查询、登录过期处理，以及基础的登录失败限流。
- 按 Token 方向设计登录凭据签发、请求校验与失效处理；本文中的“会话”指登录状态及其生命周期，不代表选用 Cookie。
- 密码使用安全的单向哈希存储，接口不返回密码哈希；不在日志中记录密码或登录凭据。
- 个人中心支持修改昵称和本人密码；修改密码验证原密码，账号身份以服务端认证结果为准。
- 退出后当前会话失效；账号禁用后旧会话不可继续访问受保护接口；密码修改或重置后所有旧会话失效，要求重新登录。
- 角色或权限变更后，下一次受保护请求按最新有效权限判定，不能一直沿用登录时的授权结果。

验收：分别验证正确登录、错误登录、退出、过期、禁用和密码变更；原凭据在对应失效条件下不可继续使用；篡改用户 ID 无法修改他人资料或密码。

### F03 用户管理

实现内容：

- 用户列表、分页、账号或昵称筛选，以及启用状态筛选。
- 创建账号、修改基本资料、启用或禁用账号、分配角色、由系统管理员重置密码。
- 账号唯一性与字段校验由服务端执行；用户管理和角色分配接口独立受权限控制。
- 防止通过禁用、撤销角色或权限等操作使系统失去最后一个可用管理员。
- 第一期以禁用作为账号退出使用的方式，暂不提供用户删除和批量操作。

验收：管理员能够创建并授权一个新账号，新账号能够登录；重复账号被拒绝；无管理权限者无法直接调用管理接口；管理员保护规则无法被绕过。

### F04 角色与权限管理

实现内容：

- 角色列表、创建、修改、停用及权限分配，支持一个用户关联多个角色。
- 通过固定权限目录勾选授权，至少覆盖用户、角色、示例记录与审计查询所需权限。
- 权限按具体操作区分，至少能分别控制示例记录的查询、新建、修改与删除；角色管理及授权操作由系统管理员执行。
- 服务端默认拒绝未经授权的受保护操作；前端根据服务端返回的有效权限控制路由、菜单和按钮。
- 停用角色后，该角色不再贡献权限；角色被用户关联时不直接删除，第一期不提供角色删除入口。

验收：创建只读角色并分配给普通账号；该账号可以查询示例记录，但直接调用写接口返回无权限结果；为同一会话撤销查询权限后，下一次查询被拒绝。

### F05 管理端基础框架

实现内容：

- 登录页、基础布局、侧边导航、顶部用户入口及面包屑导航。
- 登录态路由处理、权限受限提示、403 与 404 页面。
- 登录后进入用户有权访问的页面；没有业务菜单时提供清晰提示，并保留个人中心和退出入口。
- 统一处理加载、空数据、表单校验、操作确认、请求失败和登录过期。
- 菜单及按钮可见性与后端权限保持一致，支持刷新页面和直接访问链接。

验收：登录后刷新和直接访问合法链接正常；无权限页面、失效登录和不存在的地址各有明确反馈；只读账号界面与实际可调用权限一致。

### F06 标准 CRUD 示例

实现内容：

- 提供一个可替换的中性“示例记录”模块，包含编码、名称、状态、备注和必要的时间字段。
- 打通列表、分页、筛选、详情、新建、修改与单条删除，数据实际持久化。
- 前后端均有字段校验，服务端约束编码唯一性、分页大小和允许排序的字段。
- 删除操作有确认提示，操作成功后列表正确更新；各种操作分别执行权限校验。
- 说明如何沿用示例新增一个业务模块，以及应替换的字段、接口、权限和数据访问规则。

验收：新增记录后刷新仍然存在，修改和删除结果与数据库一致；非法输入、重复编码和未经授权的读写均被服务端拒绝。

### F07 基础审计

实现内容：

- 记录登录成功与失败，以及账号状态、密码重置、角色授权和示例记录写操作等关键事件。
- 记录事件时间、操作者、操作类型、对象标识和操作结果，提供便于关联请求的标识。
- 仅记录必要且经过筛选的字段，不保存原始密码、密码哈希、会话标识或令牌；失败操作不能记录为成功。
- 提供受权限控制的日志分页查询，支持按时间、操作者及操作类型筛选。
- 第一期开设只读查询入口，不提供日志修改、删除和导出功能；应用日志与审计记录分别承担故障定位和管理操作追溯职责。

验收：关键操作可查询并定位到操作者及对象；普通账号无法查询审计记录；抽查日志不包含敏感凭据。

| 阶段 | 交付内容 | 进入下一阶段的条件 |

## 六、交付验收清单

以下清单分别对 Java、Go 后端执行并记录结果；共用前端分别完成联调。

- [ ] 在各自独立的验收环境中，同一组接口契约场景在 Java、Go 后端均通过；各自配套前端使用相同业务页面与请求代码，无需按语言编写业务适配分支。
- [ ] 按文档准备环境，从空数据库完成迁移、管理员初始化及前后端启动。
- [ ] 管理员创建普通账号和只读角色并分配权限，普通账号能够登录并查询示例记录。
- [ ] 普通账号看不到写操作入口，直接调用写接口也被拒绝；无权限不能查询管理或审计接口。
- [ ] 授权变更后下一次受保护请求按最新权限判定；禁用账号、退出和密码变更符合约定的会话失效规则。
- [ ] 修改请求中的用户 ID 无法越权访问或修改他人个人资料与密码。
- [ ] 编码重复、非法输入和不合法分页被拒绝；正常增删改查结果可持久化。
- [ ] 对最后一个可用管理员的禁用、撤权等破坏性变更被拒绝。
- [ ] 关键事件可通过审计查询追溯，日志和响应不包含敏感凭据。
- [ ] 登录与会话失效、接口越权、本人数据边界、权限变更及管理员保护有必要的自动化验证。
- [ ] 交付实际可用的配置示例、迁移脚本、接口说明、构建启动与部署步骤，以及新增业务模块的示例说明。

## 七、实施前仍需明确的事项

1. JDK、Spring Boot、Spring Cloud，Go、Gin，以及前端工具链各自的兼容版本组合。
2. Java 侧 Spring Cloud 组件清单、两套后端各自的应用数量、服务职责和本地运行依赖。
3. PostgreSQL 生产版本、数据库脚本等资产的复用边界、Java Token 类型与组件、前端存储、有效期、刷新、多端登录及并发失效细则；Java、Go 工程与持久层工具基线已定，Go 数据库基础验证已完成，业务迁移与业务集成验收仍待实现。
4. 初始管理员的安全创建方式、登录失败限流参数和测试环境数据约定。
5. 共同接口契约的具体格式、维护与验证方式，以及两套后端的开发先后顺序和各自进度记录方式。

以上事项应在各自依赖的功能实现前确定并记录；本规划不把它们视为已实施的技术决定。
