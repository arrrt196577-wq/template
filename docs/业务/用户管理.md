## F03 用户管理

实现内容：

- 用户列表、分页、账号或昵称筛选，以及启用状态筛选。
- 创建账号、修改基本资料、启用或禁用账号、分配角色、由系统管理员重置密码。
- 账号唯一性与字段校验由服务端执行；用户管理和角色分配接口独立受权限控制。
- 防止通过禁用、撤销角色或权限等操作使系统失去最后一个可用管理员。
- 第一期以禁用作为账号退出使用的方式，暂不提供用户删除和批量操作。

验收：管理员能够创建并授权一个新账号，新账号能够登录；重复账号被拒绝；无管理权限者无法直接调用管理接口；管理员保护规则无法被绕过。

### 一、建模边界

用户提供的 `AdminUserDO` 可以对应一张管理用户表，建议命名为 `admin_user`。表保存账号、密码哈希、资料、状态与最近一次成功登录信息；登录有效记录保存在 Redis，角色及用户角色关系使用独立数据库表，后续逐项规划。

不直接照搬 Java 继承结构和 ORM 注解：

1. `TenantBaseDO` 源码尚未提供，其继承字段不确定。现有实体按此前单租户边界实现，未含 `tenant_id`；根据新增需求后续按[多租户规划](多租户.md)调整。本文显式列出审计字段，不假定就是原基类完整内容。
2. 首期暂缓部门与岗位，`deptId`、`postIds` 不进入管理账号表。后续员工档案、主部门及员工岗位关系按[员工管理](员工管理.md)独立建模，不在管理账号上重复保存组织关系或岗位 ID 的 JSON 集合；组织归属不自动授予角色。
3. `password` 改名为 `password_hash`，沿用 Go 已选定的 Argon2id。原实体中的 BCrypt 注释不适用于本项目 Go 实现；Java 的密码实现仍按其后续选型确定。

邮箱、手机、性别和头像按本次参考实体纳入可选字段草案；这不代表首期已经增加邮箱或手机登录、资料编辑接口、头像上传等功能。

### 二、管理用户表 `admin_user`

以下记录当前无租户字段的实体基线。实施迁移前须落实[多租户业务与隔离](多租户.md#多租户业务与隔离)：新增租户字段，将账号唯一性、索引和关联约束调整为租户范围，不再直接按全表用户名唯一方案建表。

#### 2.1 字段草案

`auth_version` 已加入当前 Go 管理用户和会员结构体，映射默认值 1，并标记 `json:"-"`；数据库表、正整数约束与业务行为尚未实现。其余已映射字段与当前代码核对。

下表“必填”指数据库 `NOT NULL`，不表示客户端可以提交该字段。资料字段由哪些接口开放仍须在共同契约中明确。

| 字段 | PostgreSQL 类型（建议） | 必填 | 默认值（建议） | 含义与约束 |
| --- | --- | --- | --- | --- |
| `id` | `bigint GENERATED ALWAYS AS IDENTITY` | 是 | 数据库生成 | 主键；Go 使用 `int64`，对外 ID 的字符串表达沿 API 规划建议，待契约确认 |
| `username` | `varchar(64)` | 是 | 无 | 登录账号，规范化后唯一，规则见下文 |
| `password_hash` | `text` | 是 | 无 | 完整 Argon2id 编码串，包含算法、版本、参数、随机盐与哈希；禁止明文与空串 |
| `auth_version` | `bigint` | 是 | `1` | 已加入 Go 实体；正整数约束、改密或重置时与哈希同事务递增及 JWT 版本比较尚未实现 |
| `nickname` | `varchar(64)` | 是 | 无 | 用户昵称，不唯一；创建账号时由服务层提供，禁止全空白 |
| `remark` | `varchar(500)` | 否 | `NULL` | 管理备注；不用于存放密码、Token 等敏感凭据 |
| `email` | `varchar(254)` | 否 | `NULL` | 可选联系邮箱；首期不作为登录标识，不设唯一约束 |
| `mobile` | `varchar(32)` | 否 | `NULL` | 可选联系电话；使用字符串保留前导零、加号等信息，不设唯一约束 |
| `sex` | `varchar(16)` | 是 | `'unknown'` | 建议 `unknown`、`male`、`female`；原 `SexEnum` 定义未提供，不推定数字映射 |
| `avatar` | `varchar(2048)` | 否 | `NULL` | 可选头像地址或相对资源路径；地址规则待接口设计确认，不包含上传能力 |
| `status` | `varchar(16)` | 是 | `'enabled'` | 建议 `enabled`、`disabled`；原 `CommonStatusEnum` 定义未提供，不推定 0/1 含义 |
| `last_login_ip` | `inet` | 否 | `NULL` | 最近一次成功登录的客户端 IP，兼容 IPv4/IPv6；未成功登录时为空 |
| `last_login_at` | `timestamptz(3)` | 否 | `NULL` | 最近一次成功登录时间，映射原 `loginDate`，使用有时区语义的时间点 |
| `created_at` | `timestamptz(3)` | 是 | `CURRENT_TIMESTAMP` | 创建时间，写入后不修改 |
| `updated_at` | `timestamptz(3)` | 是 | `CURRENT_TIMESTAMP` | 最近更新时间；后续更新必须由应用显式赋值，默认值不会自动随 UPDATE 变化 |
| `created_by` | `bigint` | 否 | `NULL` | 创建操作者 ID，建议自引用 `admin_user.id` 外键；初始化命令创建时可为空 |
| `updated_by` | `bigint` | 否 | `NULL` | 最近修改操作者 ID，建议自引用外键；系统操作可为空 |

首期用禁用代替用户删除，不增加 `deleted`、`deleted_at`，也不依赖 GORM 逻辑删除。不得因账号禁用而释放用户名唯一性。

#### 2.2 账号与资料规则（建议）

- 用户名：输入先去除两端空白，再将 ASCII 大写字母转为小写；规范值限制为 3–64 个 ASCII 字符，只允许小写字母、数字、下划线、点和连字符。数据库保存规范值，并设置同样的格式约束与唯一约束，避免只靠应用预查询导致并发重名。该规则尚待确认，不默认支持中文账号或手机号登录。
- 昵称：去除两端空白后为 1–64 个 Unicode 码点；Go 和 Java 采用一致的长度口径。账号创建后首期建议不支持修改用户名，避免登录标识变更规则不完整。
- 可选文本：建议将空串或全空白规范为 `NULL`；非空时执行长度和格式检查。密码原文不得 trim，密码长度与强度规则另行确认，不能用哈希列长度代替输入规则。
- 联系信息：邮箱、手机是否验证及号码格式尚未确定；暂不据此授权、登录或找回密码。展示和日志只保留业务必要信息。
- 头像：存储地址不代表允许后端主动抓取任意 URL；上传、地址来源和前端展示限制在实际开放功能前确定。

#### 2.3 约束与索引（建议）

| 名称 | 类型 | 目的 |
| --- | --- | --- |
| `pk_admin_user` | 主键 `id` | 唯一标识用户 |
| `uk_admin_user_username` | 唯一约束 `username` | 约束规范化后的账号唯一性，同时支持登录查询 |
| `ck_admin_user_username` | CHECK | 校验账号字符范围及 3–64 长度，禁止非规范值绕过唯一性规则 |
| `ck_admin_user_nickname` | CHECK | 拒绝空白昵称，应用层仍执行相同的 Unicode 校验规则 |
| `ck_admin_user_password_hash` | CHECK | 拒绝空哈希；编码格式与参数有效性由密码组件负责 |
| `ck_admin_user_status` | CHECK | 限定为 `enabled`、`disabled` |
| `ck_admin_user_sex` | CHECK | 限定为 `unknown`、`male`、`female` |
| `fk_admin_user_created_by` | 外键，自引用，`ON DELETE RESTRICT` | 保留创建操作者引用；允许初始化时为空 |
| `fk_admin_user_updated_by` | 外键，自引用，`ON DELETE RESTRICT` | 保留最近修改操作者引用；允许系统操作时为空 |
| `idx_admin_user_created_at_id` | B-tree `(created_at DESC, id DESC)` | 支持 API 规划建议的默认分页顺序 |

不重复为主键和用户名创建普通索引。状态字段取值少，暂不单独创建索引；状态组合索引和昵称模糊查询索引依据数据规模、查询与执行计划再增加。

### 三、写入、认证与审计边界

- 持久化实体、业务类型与 HTTP DTO 分离。响应 DTO 不包含 `password_hash`；更新按白名单映射，客户端不能直接修改 ID、哈希、角色、创建人或最近登录信息。备注和联系方式也应按权限选择性返回。
- 创建用户必须通过密码组件生成哈希，不设置默认密码；初始管理员通过受控命令创建，具体交互和幂等策略待定。管理员身份由后续 RBAC 模型确定，不以 `id = 1`、用户名或额外的 `is_admin` 字段推定。
- 登录成功并建立会话时才更新 `last_login_at`、`last_login_ip`；并发登录应保证较早的成功事件不会覆盖较新的时间及其对应 IP。失败登录不覆盖成功登录信息，另写失败审计。IP 来自已经配置可信代理边界的服务端解析，不能直接信任客户端传入字段。
- 最近登录字段只提供摘要，不能替代登录历史、会话记录或关键操作审计。`created_by`、`updated_by` 也不能替代完整审计事件；登录摘要自动更新时不冒充某个后台资料修改操作者。
- 禁用账号、修改或重置密码必须按既定要求撤销旧会话；账号变更与成功审计由 PostgreSQL 事务控制，Redis 凭据撤销不能加入该事务；改密/重置以同事务递增 auth_version 保证后续认证拒绝旧版本，Redis 旧记录清理不作为改密成功前提；禁用与租户级失效机制仍需细化。重新启用账号不得恢复被撤销的会话。
- 仅靠本表无法保证并发登录与改密/禁用时的撤销边界，也无法保护最后一个可用管理员。相关用例须结合会话、角色关系以及明确的锁或其他并发控制另行设计和测试。
- `timestamptz` 保存时间点，应用与数据库连接使用统一 UTC 约定；HTTP 时间表达仍须在共同契约中确认，不能直接照搬无时区的 `LocalDateTime` 表达。
