## Token 鉴权设计边界

多租户需求见[多租户业务规划](../业务/多租户.md)及[接口边界](多租户.md)，尚未落实共同契约。后续登录须明确目标租户及管理端/会员身份；会话绑定租户，请求不能用客户端租户值覆盖已认证范围，并须检查租户状态。本文接口清单不是完整的多租户定义，Java、Go 与前端须同步补齐后再实现。

### 外部交互（部分已确定）

JWT 内的 jti、authVersion、Redis Key 与有效记录、会员多端独立登录及故障边界统一见[业务规划：账号管理与登录凭据](../业务/认证与个人中心.md#账号管理与登录凭据)。Session 仅为一次独立登录的业务称呼，不指框架状态容器；本方案仍需要服务端有效记录。

- 已确定受保护请求统一通过 `Authorization: Bearer <token>` 传递 Token；Token 类型已选择 JWT，但不代表采用 OAuth 2.0 完整流程或第三方登录。
- 登录接口校验用户名密码后返回 Token 及有效期信息；候选字段为 `accessToken`、`tokenType`、`expiresIn`，其中 `expiresIn` 单位为秒，具体有效期待定。
- 前端将 Token 视为不透明字符串，不从 JWT 内容或其他内部格式推导权限、身份及过期结论；用户信息与有效权限由当前用户接口提供。
- 建议部署环境通过 HTTPS 传输，登录响应设置 `Cache-Control: no-store`；Token 不放入 URL，不记录在应用日志或审计中。
- 对受保护接口的 401 响应按 Bearer 约定返回 `WWW-Authenticate`；不将项目 RBAC 权限标识自动等同于 OAuth scope。

Bearer 请求头及凭据保护要求参考 [RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html)。本项目的用户名密码登录接口不因此被视为 OAuth Token Endpoint。

### 必须满足的行为

以下要求已来自业务规划，不因 Token 类型选择而放宽：

| 触发事件 | 后续请求要求 |
| --- | --- |
| 当前登录退出 | 当前登录的 Token 不可继续访问受保护接口 |
| 账号禁用 | 该账号已有 Token 不可继续访问受保护接口 |
| 本人修改密码或管理员重置密码 | 该账号全部旧 Token 失效，要求重新登录 |
| 角色停用、角色分配或权限变更 | 下一次受保护请求按最新有效权限判定 |
| Token 到期或被篡改 | 服务端拒绝，前端按统一认证错误处理 |

仅清除前端 Token 不能完成服务端退出。认证改为 JWT + Redis 有效记录，每次请求先验证 JWT，再检查其 jti 对应的 Redis 记录，并查询数据库账号 auth_version、账号/租户状态与最新权限，严格比较 JWT authVersion；不再采用 PostgreSQL 登录记录方案。会员单次退出仅撤销当前 jti，其他登录继续有效。改密、重置密码、禁用账号或租户按既定范围使旧凭据全部失效；改密/重置通过同一数据库事务更新密码哈希并递增 auth_version，使全部旧版本失效；禁用、租户级撤销及其他并发控制细节待定。Redis 缺失记录不能从 JWT 自动重建，Redis 不可用不能仅验签放行。Java、Go 独立部署，不要求共享记录或互认 JWT。

Go 密码哈希选定 Argon2id，参数与编码规则在实现前确定；使用 RBAC 关系表和统一授权中间件，首期不接入 Casbin。上述方案尚未实现；并发失效、事务边界和最后管理员保护须有专门设计与验证。

若引入刷新 Token，退出、账号禁用及密码变更还须使相应刷新能力失效，明确轮换、重放处理和并发刷新规则；尚未确定前，不将刷新接口列为必做项。

### 首条登录链路前需确定

1. 两套后端 JWT 库、签名算法、密钥与轮换、签发者/受众、jti 生成规则；Redis 记录格式与可选用户索引、auth_version 的并发更新 SQL，Go 密码哈希参数与组件版本。
2. 登录响应和 401 错误的完整字段及头部；Bearer 传递已确定。
3. 前端存储方式及刷新页面后的登录体验；不默认写入 localStorage 或 sessionStorage，也不改用 Cookie 保存凭据。
4. 有效期、刷新、管理端多端策略及并发撤销规则；会员多端独立登录与当前凭据登出范围已定，两套后端落实相同对外行为。
5. 前后端跨域时的允许来源、`Authorization` 预检、响应头暴露及请求标识传递配置。

## 模块接口清单（建议路径）

路径均相对于 `/api/v1`，路径和 DTO 尚未实现；具体权限码目录待确定；系统管理员身份及最后一个可用管理员保护必须由服务端验证。通用请求、响应、状态码、分页和校验遵循[公共规范](公共规范.md)，功能范围与验收见对应业务文档。未给出 DTO 的接口，须在开发前补齐字段、约束、成功与失败响应，不能根据清单推定完整契约。

| 模块 | 方法与路径 | 用途与授权边界 |
| --- | --- | --- |
| 认证 | `POST /auth/login` | 用户名密码登录，公开入口，执行失败限流 |
| 认证 | `POST /auth/logout` | 撤销当前登录，要求有效认证 |
| 个人中心 | `GET /me` | 返回本人资料及有效权限，不返回密码哈希或 Token |
| 个人中心 | `PATCH /me` | 仅修改本人昵称等白名单资料 |
| 个人中心 | `POST /me/change-password` | 验证原密码，修改后撤销全部旧凭据 |
